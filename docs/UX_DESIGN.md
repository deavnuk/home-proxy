# UX 设计规范

> 对应 [PRD](PRD.md) F-7.x。本文定义**具体的交互与视觉规则**，不是泛泛而谈的原则。

---

## 1. 设计原则

### P1 一眼可知状态
用户打开面板 3 秒内必须回答："现在正常吗？"

**落地**：顶部常驻体检徽标（绿/黄/红点 + 通过项数），不需要翻页。

### P2 每个红灯都给出下一步
错误信息必须包含「哪里错了 + 怎么做」。

**反例**：`HTTP 500`、`Not Found`、`failed`
**正例**：`nft 规则未加载 —— 在宿主机执行： sudo nft -f ...`（附可点击复制的命令块）

### P3 危险操作二次确认，可逆操作不打断
- 删除订阅 → `confirm`，并说明后果
- 切换节点、暂停日志 → 立即执行 + toast

### P4 就地反馈，不跳页
所有写操作在当前页面显示 loading → 成功/失败，**不重新加载整页**。

### P5 键盘可用
所有交互元素可用 Tab 到达、Enter/Space 触发，焦点可见。

## 2. 视觉体系

### 2.1 间距（8px 基准）
| token | 值 | 用途 |
|---|---|---|
| xs | 4px | 图标与文字 |
| sm | 8px | 紧凑元素内边距 |
| md | 12px | 卡片内元素间距 |
| lg | 18px | 卡片内边距 |
| xl | 26px | 区块间距 |

### 2.2 字号阶梯
| 级别 | 大小 | 用途 |
|---|---|---|
| display | 25px | 统计数字 |
| h1 | 20px | 页面标题 |
| h3 | 13.5px | 卡片标题 |
| body | 13px | 正文 |
| small | 11.5px | 徽标、辅助 |
| mono | 11.5–12.5px | 技术数据 |

### 2.3 语义色（只用于状态，不做装饰）
| 状态 | 色值 | 用在哪 |
|---|---|---|
| ok | `#3ddc97` | 检查通过、节点可达、徽标 ok |
| warn | `#ffc857` | 容器内无法检测、节点延迟中 |
| err | `#ff6b81` | 检查失败、节点不可用 |
| neutral | `--txt-3` | 无数据、未知 |

**规则**：一个屏幕内红/黄点不超过 1 个显著位置，避免视觉噪音。

### 2.4 动效
| 场景 | 时长 | 缓动 |
|---|---|---|
| hover | 160ms | `cubic-bezier(.4,0,.2,1)` |
| 弹层出现 | 200ms | 同上 |
| 状态点脉冲 | 1200ms | `ease-in-out` 循环 |

**必须**：`prefers-reduced-motion: reduce` 时全部降为 1ms。

## 3. 组件规范

### 3.1 体检项 CheckItem
```
┌─────────────────────────────────────────────┐
│ ✓  mihomo 进程                              │
│    运行中，版本 v1.19.34                     │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│ ✕  nft 规则                                 │
│    宿主机未加载 inet transp 表               │
│    ┌───────────────────────────────────┐   │
│    │ sudo nft -f /opt/.../nft.conf     │   │  ← 点击复制
│    └───────────────────────────────────┘   │
└─────────────────────────────────────────────┘
```
- 图标：✓ / ! / ✕ 三种，形状区分（不只靠颜色）
- 修复命令用 `<pre>`，`cursor: copy`，点击复制 + toast

### 3.2 空状态
必须包含**下一步动作**，不能只有"暂无数据"。

```
┌────────────────────────────────────────┐
│         还没有订阅                      │
│  点右上角「+ 添加订阅」填入订阅链接       │
└────────────────────────────────────────┘
```

### 3.3 加载态
| 场景 | 表现 |
|---|---|
| 首屏 | 骨架屏（灰块 + 微光动画）|
| 按钮点击 | 文字变灰 + `disabled`，不换文案（避免布局跳动）|
| 列表刷新 | 保留旧数据 + 顶部细进度条，**不清空** |

**反模式**：清空列表然后转圈（用户会以为数据丢了）。

### 3.4 Toast
- 位置：底部居中，距底 26px
- 时长：2.6s，可叠加（新的替换旧的）
- 成功：中性背景；失败：红色背景 + `role="alert"`

### 3.5 弹层 Modal
- 遮罩 `rgba(3,6,12,.72)` + `backdrop-filter: blur(6px)`
- **Esc 关闭**、点击遮罩关闭
- 打开后焦点进第一个输入框
- 关闭后焦点回到触发按钮

## 4. 交互规则

### 4.1 表单校验时机
| 时机 | 校验 |
|---|---|
| 输入中 | 不校验（不打断）|
| 失焦 | 格式校验（如 URL 前缀）|
| 提交 | 全量校验 + 服务端校验 |

### 4.2 危险操作
```js
confirm(`确定删除订阅「${name}」？

它会从配置文件中移除，相关节点将不再可用。`)
```
必须说明**后果**，不只是"确定吗？"

### 4.3 轮询与暂停
- `document.hidden` 时暂停所有轮询
- 日志页：用户上滚超过 80px 时暂停自动滚动，显示「↓ 有新日志」浮标

### 4.4 键盘快捷键
| 键 | 动作 |
|---|---|
| `1`–`8` | 切换页面 |
| `r` | 刷新当前页 |
| `Esc` | 关闭弹层 |
| `?` | 显示快捷键列表 |

## 5. 响应式

| 断点 | 布局 |
|---|---|
| ≥860px | 左侧栏 228px + 主区 |
| <860px | 顶部横向导航 + 单列卡片 |

移动端必须保证：
- 统计卡 2 列（不是 1 列，避免过度滚动）
- 表格可横向滚动，首列 sticky
- 弹层宽度 `min(520px, 100%)`，最大高 88vh 可滚

---

## 6. 可访问性（a11y）

| 项 | 要求 |
|---|---|
| 焦点 | 所有可交互元素 `:focus-visible` 有明显描边（3px 半透明强调色）|
| 对比度 | 正文 ≥ 4.5:1，辅助文字 ≥ 3:1 |
| 图标 | 状态图标必须配文字，不单独用颜色传达信息 |
| 语义 | 导航 `<nav>`、状态区 `role="status"`、错误 `role="alert"` |
| 屏幕阅读器 | 动态更新区域用 `aria-live="polite"` |
| 触控 | 点击目标 ≥ 32×32px |

## 7. 文案规范

| 场景 | 规则 | 例 |
|---|---|---|
| 按钮 | 动词开头，≤4 字 | 「添加订阅」不是「订阅」|
| 错误 | 说清原因 + 下一步 | 「订阅链接必须以 http:// 开头」|
| 空状态 | 说明 + 引导动作 | 「还没有订阅 → 点右上角添加」|
| 确认框 | 说明后果 | 「删除后相关节点将不可用」|
| 成功提示 | 简短过去式 | 「已保存」「已删除」|

**禁止**：`出错了`、`操作失败`、`系统异常`（信息量为零）。

# 第二轮重构：从「模块」到「任务」

## 问题

第一版按后端模块划分导航（代理 / 订阅 / 规则 / 连接 / 日志 / 设置 / 配置文件），
用户实际使用时遇到三个障碍：

| 用户想问 | 第一版要怎么做 | 症结 |
|---|---|---|
| 「家里能上网吗？」 | 概览看数字 → 连接看状态 → 日志看错误 | 三处拼凑，没有结论 |
| 「这网站为啥走代理？」 | 规则页 7 个规则集 + 一张 20 万行表 | 看不懂，也查不到具体网站 |
| 「换个节点」 | 代理页 3 个策略组（fallback/url-test/select） | 内部概念，不知道该点哪个 |

## 重构原则

1. **一屏一个结论**，不要一屏一堆数据
2. **名词用用户语言**，不用 mihomo 术语
3. **常用功能进主路径**，高级功能需二级展开
4. **每个危险操作都要有说明**，不能只有按钮

## 新信息架构（5 页）

| 页面 | 回答的问题 | 关键设计 |
|---|---|---|
| **家里** | 能不能上网？不能是哪里坏了 | 顶部判定卡（绿/黄/红 + 一句话），三张快捷卡，流量图 |
| **分流** | 哪些网站走代理？ | 顶部「查网站」输入框 → 直接给结论；我的规则可增删；自动清单折叠 |
| **节点** | 用哪个节点？ | 订阅（来源）→ 当前使用（中文组名）→ 全部节点（可排序搜索）|
| **诊断** | 深层问题在哪？ | 7 项体检（失败给可复制命令）+ 活动连接 + 实时日志 |
| **设置** | 内核参数 | 开关、端口、配置文件（折叠）|

## 逐项改动

### 概览 → 家里

**改前**：4 张统计卡 + 透明代理链路 + 内核信息（都是数字，没有结论）
**改后**：
- **判定卡**：`✓ 一切正常` / `需要处理` + 一句话原因 + 「查看 N 项问题」按钮
- 三张快捷卡：代理模式（智能/全局/直连）、当前节点、测速
- 流量图放大到 140px，带网格和渐变填充

**依据**：用户打开面板 90% 是确认「有没有问题」，只有 10% 才看细节。

### 规则 → 分流

**改前**：6 个规则集（gfw/cncidr/direct/private/reject）+ 20 万行规则表
**改后**：
- **「这个网站会走代理吗？」** 置顶 —— 输入域名直接给结论和原因
- 「我指定的网站」可增删，覆盖自动判断
- 自动清单用中文命名：`常见被墙网站（gfwlist）`、`国内 IP 段（直连）`
- 完整规则表**默认折叠**，标注「这张表给排查用，日常不需要看」

**探测实现三选一**（都试过）：
| 方案 | 结果 |
|---|---|
| mihomo `/dns/query` API | ✗ 走真实解析，google 也返回真实 IP |
| 直接查 mihomo DNS 端口 1053 | ✗ 容器被宿主 ufw 拦截 |
| **直接匹配规则集文件** | ✓ 规则集挂在容器内，且这正是分流的真实依据 |

匹配顺序与 `rules:` 一致：我的规则 → direct 清单 → gfw 清单 → 兜底直连。

### 代理 → 节点

**改前**：策略组显示 `fallback` / `auto` / `node-manual`，用户不知道区别
**改后**：
- 组名中文化：`主线路（挂了自动切下一个）`、`自动择优（选延迟最低的）`
- 类型中文标注：`手动选择` / `按顺序容灾` / `自动选最快`
- 节点列表加**排序**（默认/延迟/名称）和**搜索**
- 隐藏 `GLOBAL` 等内部组

### 配置文件

**改前**：主导航一个页面，直接给 YAML 文本框
**改后**：收进「设置 → 配置文件」，附说明「保存会自动备份并热重载，语法错误会被拦截」

## 文案对照

| 改前（术语） | 改后（人话） |
|---|---|
| `RULE-SET,gfw,PROXY` | 「在 gfwlist（被墙网站清单）里，会走代理」 |
| `fallback` | 「主线路（挂了自动切下一个）」 |
| `URLTest` | 「自动选最快」 |
| `fake-ip` / `198.18.x.x` | 不出现 |
| `订阅 proxy-providers` | 「订阅是机场或自建面板给的链接」 |
| 空表格 | 「还没有指定任何网站。自动分流判断不准时，点右上角「+ 指定一个」覆盖它。」 |
