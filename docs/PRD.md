## 1. 产品定位

**一句话**：让不懂网络的家人也能用上"自动按需翻墙"的家庭网络，且管理员不必登服务器改配置。

**不是**什么：
- 不是给极客玩的 Clash 图形壳（那些已经很多了）
- 不是机场客户端（我们不卖节点）
- 不是路由器固件

**核心价值**：把「DNS 分流 + TPROXY + 规则订阅 + 节点容灾」这套复杂机制，包装成**改两个下拉框就能跑**的东西。

---

## 2. 用户画像

### P1 — 管理员（本人，技术背景）
- 部署一次，之后**不想再登服务器**
- 关心：节点是否可用、规则是否过期、流量是否异常
- 痛点：改个订阅要 SSH 进去改 YAML、重启进程

### P2 — 家庭成员（非技术）
- 完全不知道有代理存在
- 唯一诉求：**网能上，别卡**
- 痛点：配置出错时只会说"网坏了"

### P3 — 临时访客
- 连 Wi-Fi 即用
- 不关心任何配置

## 3. 核心用户旅程

### J1 首次部署（管理员，一次性）
```
拿到仓库 → 改 2 处（订阅 URL、面板密码）→ 跑一个脚本 → 打开面板确认绿灯
```
**验收**：从零到全屋可用 ≤ 15 分钟，全程不问"下一步做什么"。

### J2 日常查看（管理员，每周）
```
打开面板 → 一眼看到：节点是否活着 / 今天的流量 / 有没有报错
```
**验收**：3 秒内判断"一切正常"，异常时能直接看到原因。

### J3 换订阅/加节点（管理员，偶发）
```
面板「订阅」页 → 粘贴链接 → 保存 → 自动生效
```
**验收**：**不需要 SSH，不需要改 YAML，不需要重启进程**。

### J4 排障（管理员，出问题时）
```
面板显示红灯 → 点开看具体原因和建议命令 → 照做 → 变绿灯
```
**验收**：常见故障（nft 未加载 / 节点全挂 / 订阅过期）都能自助解决。

### J5 家人上网（家庭成员，每天）
```
啥也不做，直接上网
```
**验收**：被墙站点可用，国内站点速度不受影响。

## 4. 需求清单

> 优先级：P0 = 没有就不算"好用"；P1 = 明显提升体验；P2 = 锦上添花

### 4.1 订阅管理（P0）

| ID | 需求 | 验收标准 |
|---|---|---|
| F-1.1 | 面板内新增订阅 | 输入名称+URL 即可添加，自动写 config.yaml 并热重载 |
| F-1.2 | 修改订阅 URL | 改完立刻生效，旧节点被替换 |
| F-1.3 | 删除订阅 | 删除后节点从策略组消失，配置同步更新 |
| F-1.4 | 启用/停用订阅 | 停用后不参与分流，但保留配置 |
| F-1.5 | 手动刷新订阅 | 一个按钮重新拉取，显示节点数变化 |
| F-1.6 | 订阅状态可视化 | 显示：节点数、可用数、流量用量、到期时间、最后更新时间 |
| F-1.7 | 拉取失败可见 | 显示错误原因（404/超时/格式错误），不静默失败 |

**为什么是 P0**：当前必须 SSH 改 YAML。这是最高频的运维动作，也是最容易出错的动作。

### 4.2 配置持久化（P0）

| ID | 需求 | 验收标准 |
|---|---|---|
| F-2.1 | 设置页改动落盘 | 改运行模式/日志级别后写入 config.yaml |
| F-2.2 | 保存前校验 | YAML 语法错误、缺关键字段时拒绝保存并提示 |
| F-2.3 | 失败自动回滚 | 热重载失败自动恢复上一版配置 |
| F-2.4 | 改动历史 | 保留最近 N 个备份，可一键恢复 |

**为什么是 P0**：当前设置改完重启就没，用户以为是 bug。

### 4.3 开机自启（P0）

| ID | 需求 | 验收标准 |
|---|---|---|
| F-3.1 | mihomo 由 systemd 托管 | 崩溃自动重启，开机自动启动 |
| F-3.2 | socket 路径固定 | 重启后 UI 自动重连，无需人工干预 |
| F-3.3 | 服务状态可见 | 面板显示 mihomo 运行时长、重启次数 |

**为什么是 P0**：实测中机器重启一次，UI 就连不上了。

### 4.4 日志查看（P0）

| ID | 需求 | 验收标准 |
|---|---|---|
| F-4.1 | 面板内看实时日志 | 支持级别过滤（info/warning/error）|
| F-4.2 | 日志可搜索 | 按域名/关键词过滤 |
| F-4.3 | 分流决策可见 | 能看到 `xxx --> google.com match RuleSet(gfw) using PROXY` |

**为什么是 P0**：当前排障必须 SSH 看 journalctl。

### 4.5 代理节点管理（P1）

| ID | 需求 | 验收标准 |
|---|---|---|
| F-5.1 | 节点搜索 | 按名称过滤 |
| F-5.2 | 延迟排序 | 升序/降序切换 |
| F-5.3 | 批量测速 | 一键测所有节点，进度可见 |
| F-5.4 | 一键选最快 | 测完自动切到最低延迟节点 |
| F-5.5 | 节点来源标记 | 区分手写节点 / 订阅节点 |

### 4.6 流量与健康度（P1）

| ID | 需求 | 验收标准 |
|---|---|---|
| F-6.1 | 流量曲线 | 保留最近 5 分钟（服务端缓冲，刷新页面不丢）|
| F-6.2 | 累计流量 | 上行/下行/总计 |
| F-6.3 | 一键体检 | 检查：转发/mihomo/nft/策略路由/节点可用性/规则集时效 |
| F-6.4 | 体检给建议 | 每个红灯都给出**可复制的修复命令** |

### 4.7 界面体验（P1）

| ID | 需求 | 验收标准 |
|---|---|---|
| F-7.1 | 深浅主题切换 | 记住选择，跟随系统 |
| F-7.2 | 加载态 | 骨架屏，不是空白 |
| F-7.3 | 错误态 | 明确说"哪里错了 + 怎么办"，不是 `HTTP 500` |
| F-7.4 | 移动端可用 | 手机上能看状态、能切代理 |
| F-7.5 | 操作反馈 | 所有写操作有 loading + 成功/失败提示 |

### 4.8 安全与权限（P1）

| ID | 需求 | 验收标准 |
|---|---|---|
| F-8.1 | 面板鉴权 | HTTP Basic，可关闭但明确警告 |
| F-8.2 | 只读模式 | 一键锁定，防止误改 |
| F-8.3 | 敏感信息脱敏 | 订阅 token、密码不在 UI 明文显示 |

### 4.9 数据可移植（P2）

| ID | 需求 |
|---|---|
| F-9.1 | 配置导出/导入 |
| F-9.2 | 备份列表与恢复 |
| F-9.3 | 一键复制诊断报告（贴给他人求助）|

## 5. 关键约束

1. **数据面与控制面分离**：TPROXY 必须走宿主机 root；UI 是容器。两者通过 unix socket 通信（宿主防火墙会拦 TCP）。
2. **不改宿主防火墙**：不能要求用户 `ufw allow`，UI 必须走 docker 端口发布。
3. **订阅失效不能拖垮代理**：拉取失败保留旧配置，继续服务。
4. **单机部署**：不引入数据库、消息队列等外部依赖。
5. **零前端构建**：不引入 npm/webpack，保持"改完刷新即可"。

## 6. 非目标（明确不做）

- ❌ 多租户/多用户角色
- ❌ 节点测速历史曲线
- ❌ 按设备分配不同策略
- ❌ 内置节点购买/试用
- ❌ 流量计费
- ❌ 自己的 DPI 引擎（复用 mihomo 规则）

## 7. 成功指标

| 指标 | 当前 | 目标 |
|---|---|---|
| 首次部署耗时 | ~40 分钟（需查文档多处）| ≤ 15 分钟 |
| 换订阅需要 SSH | 是 | **否** |
| 重启后需人工干预 | 是 | **否** |
| 排障需要 SSH | 是 | **否**（常见故障）|
| 面板首屏可用判断 | 需逐项看 | **一眼红/绿灯** |
